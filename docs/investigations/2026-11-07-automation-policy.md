# #9 自動送信・承認操作の方式調査

調査日: 2026-11-07。状態: Investigation Complete。実装は行わない。

## 結論

現行のユーザー操作による挿入・貼り付け・クリアを維持する。ChatGPT Webへの自動送信・自動承認は本作業で追加しない。将来の処理開始は、明示操作でCodexBridgeの既存MCPまたは正式APIを呼ぶ方向を優先する。これは今回の調査判断であり、既存機能へ新たな安全ゲートを加える変更ではない。

## 一次資料と適用範囲

- [OpenAI Terms of Use](https://openai.com/policies/terms-of-use/): 取得ページの発効日は2026-01-01。個人向け利用条件には、データ・Outputの自動抽出、制限や保護措置の迂回に関する禁止がある。APIや法人向けサービスには別条件が適用される旨も記載されている。
- [Computer use integration recipes](https://developers.openai.com/api/docs/guides/tools-computer-use-integration): 正式なComputer useの実装指針。外部コンテンツとユーザー指示を分け、認証を伴う操作や不可逆な操作の扱いを定めている。ChatGPT Webの任意の自動化に対する包括許諾を示す文書ではない。
- [Codex App Server](https://learn.chatgpt.com/docs/app-server): threadの一覧・読取、turn開始、進行通知、完了通知を提供する正式なクライアント接続方式。既存デスクトップアプリと別プロセスを立てたときの実行状態共有まで、この資料だけで保証しない。
- [MCP servers](https://developers.openai.com/api/docs/guides/tools-connectors-mcp): ツール連携の正式経路。任意のLANサーバーへのChrome拡張接続やChatGPT Web操作の許諾を保証するものではない。

## 方式比較

| 方式 | 技術面 | 利用条件面・判断 |
| --- | --- | --- |
| 明示クリックで現在のComposerへ挿入 | 現行実装。execCommandと選択範囲を使用。DOM変更の影響あり | 既存機能を維持。送信自動化の承認とは扱わない |
| ChatGPT Webの送信ボタンを自動クリック | 技術的にはDOMイベント処理が必要。SPA・IME・レイアウト変更・再試行で誤送信の余地 | 一般的な利用条件だけでは特定の運用の許諾を確定できず判断保留。今回はユーザー指示により実装対象外 |
| 承認ダイアログの一括自動クリック | 操作ごとの対象・権限・副作用を識別しないと意味が変わる | 人間の意思決定を代替する包括実装は対象外。将来必要なら操作単位の仕様を別Issueにする |
| ChatGPT内部API・ブラウザの認証情報を転用 | 公開契約のない通信・資格情報に依存 | 本プロジェクトでは不採用。認証情報の取得・利用は実施していない |
| OpenAI正式API | 公開インターフェースでアプリが入出力を管理できる | API契約・利用条件の範囲で別アプリとして検討可能。既存ChatGPT Web会話と同じ履歴・状態とはみなさない |
| CodexBridge既存MCP | 既存のthread/task系ツールを再利用できる。#17で能力を検証 | 明示操作によるCodex処理開始の優先候補。ChatGPT Webの自動送信は伴わない |

「Webのすべての自動操作が一律禁止」「公式Computer useがあればどのサイト操作も許諾済み」のいずれも、この調査からは結論できない。個々の運用、適用契約、取得する情報と操作範囲を切り分ける。

## 実装へ進む場合の作業範囲

今回の明示制約どおり、Web自動送信・承認は実装しない。将来の別依頼では、対象サービス・適用契約・ユーザーが直接起動する操作と送信データを具体化し、既存MCPで充足するかを先に確認する。Chrome権限・外部サービス・既存保存形式はこの調査では変更していない。
