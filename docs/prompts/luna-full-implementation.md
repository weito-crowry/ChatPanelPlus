# ChatPanelPlus 全機能実装：Codex Luna マスター指示文
> **実装開始条件:** この文書は実装指示の保存用。ChatGPT側での文書作成、CodexBridgeを通じた保存・参照、文書の存在、会話上の承認だけでは実装を開始しない。ユーザーが **Codex App内で** この文書を用いた明示的な実装開始指示を投入した時点のみ実装を開始する。


## 役割

あなたは ChatPanelPlus の **実装オーケストレーター兼自己レビュー責任者** です。Codex の **Luna** として動作し、実装担当には **Luna サブエージェント** を使用してください。

この指示は、今回の実装プロジェクトについて **サブエージェント使用を明示的に許可する指示** です。既存 AGENTS.md の「原則として単一エージェント」からの今回限りの例外として扱い、AGENTS.md のその他の規約は守ってください。

- オーケストレーター：Luna。計画、依存関係管理、タスク分割、差分監査、自己レビュー、統合テスト、進捗管理を担当。
- 実装者：Luna サブエージェント。指定タスクのコード・テストを実装し、結果を報告。
- 実装タスクは **一度に1件、逐次実行**。並列編集、階層的なサブエージェント委任、新 worktree は禁止。
- Luna のサブエージェント利用可否とモデル指定を実環境で確認する。**Luna と確認できないモデルに無断で置き換えない**。Lunaサブエージェントを利用できない場合は実装を開始せず、制約を報告する。
- ChatGPT による最終独立レビューは、あなたの自己レビューと別工程。自分のレビューを「独立レビュー済み」と扱わない。

2. 指示、会話制御、壁打ち、二択、四択の5タブと全定型文
3. 入力欄の先頭挿入、現在位置へのペースト、選択範囲置換、クリア
4. v7.2 とユーザー提供スクリーンショットにできる限り近い初期配置・外観
5. タブ切替の記憶、左端可視タブを初期値とする選択、最小化・復元と永続化
6. ボタン表示/非表示、ボタン順変更、ラベル編集、色編集、タブ順変更、タブ表示/非表示、定型文編集、初期化の8設定項目

8. SPA遷移とComposer再生成からの復帰、エラー通知、性能劣化と二重マウントの防止

**自動送信は絶対に実装しない。** 未送信の文章・空白・改行・選択範囲を意図せず変更せず、部分編集のために入力欄全体を再構築しない。チャット本文やクリップボード内容をログ・保存・外部送信しない。実行アクションとして任意JavaScriptを受け付けない。

既定の文面、ID、色、長文プロンプトは **03-prompt-actions.md が正本**。長文を要約・改変しない。

通知、Codex連携、独自の自動送信機能はこのプロンプトの実装対象に含めない。会話統計は別途承認済みの CPP-DESIGN-12（会話統計 Phase 1～4）で扱う。

## 実装手順

### Phase 0：事前確認・基準点の記録

- AGENTS.md、設計書、ソース、テスト、package.json、manifest、Git状態を実際に確認する。
- 現行 main が unborn branch で既存ソースも未追跡である前提を検証する。git diff だけで変更の有無を判断しない。
- 既存ファイル一覧、関連ファイルのハッシュ・サイズ、現在の実装構成を記録し、以後の変更対象を追跡する。**初回コミットは行わない**。
- 設計と現行コードに重大な矛盾があれば、変更せず整理して報告する。そうでなければ次のPhaseへ進む。

### Phase 1：定義・共通型・既定値

- v7.2 の20ボタン・5タブの安定ID、色、並び、全文の定型文を共有データとして定義。
- 表示値と操作IDを分離し、必要な共通型・既定値解決関数を追加。
- 03-prompt-actions.md との原文一致テストを作成。

### Phase 2：入力欄アダプター

- Composer の安全な特定、Range／フォーカス、先頭挿入、選択位置挿入、クリアを UI から独立実装。
- ProseMirror/Lexical 互換、空白・改行保全、自動送信なしをテスト。
- まず単一ボタンで挿入経路を確認できる構造にする。実機未確認はそのように記録。

### Phase 3：Reactパネルと全定型ボタン

- 既存 Shadow DOM／Reactの骨格を流用して、常時表示群と5タブ、20ボタンを描画。
- 初期見た目は画像・02-panel-ui.md・v7.2 CSS に近づける。
- 最初から全機能を密結合せず、表示層とアクション層を分離。

### Phase 4：タブ選択・最小化

- 左端可視タブの初期選択、有効な既存選択の復元、タブ切替・最小化／復元。
- 全タブ非表示、選択タブ非表示などの境界条件をテスト。
- この段階で永続化インターフェースを整備し、Phase 6 と整合させる。

### Phase 5：クリップボードとフォールバック

- コピペボタン、選択位置のスナップショット、Clipboard API 読取、手動貼付ダイアログ。
- **読取開始時と挿入直前で Composer Element が異なる場合、同じ会話内の再生成でも自動挿入を中止して再試行を通知。新Composerへのフォールバック挿入は禁止。**
- 同一ComposerでRangeだけが無効な場合は、現在の有効Range、なければ末尾という仕様を守る。
- クリックから完了までの段階別所要時間・結果をテスト用に計測可能とし、本文は記録しない。

### Phase 6：保存・Options・インポート／エクスポート

- chrome.storage.local を利用した schema 検証、変更通知、設定保存・復元・初期化。
- Optionsで全8設定項目を編集できるようにする。
- 保存前ドラフト、適用時バリデーション、競合・エラー表示、JSON往復と不正ファイル防御を実装。
- 既存 v7.2 localStorage の自動移行は、未決定なら勝手に行わない。

### Phase 7：ライフサイクルとUI統合

- ChatGPTのSPA遷移、DOM再構築への再アタッチ、重複React Root/Observer防止。
- 既存会話読み込みを妨げないこと、未送信入力を維持することを重視。
- ライト・ダーク・狭い画面での見た目を調整。
- 右下「ChatPanelPlus 設定」導線は、未決定の統合仕様を勝手に変更せず既存動作を保つ。

### Phase 8：全体検証と提出

- pnpm check:size、pnpm lint、pnpm typecheck、pnpm test、pnpm build を実行し、実測結果を報告。pnpm test はビルドを伴う点に留意。
- 新機能テストを追加し、既存テストとの回帰を確認する。
- 実機で確認していない部分は「未検証」。スクリーンショット・ChatGPT画面への実アクセスなしで視覚完全一致を断言しない。
- **ユーザー承認なしで deploy:chrome へ進まず**、Chrome手動検証の手順と期待結果を提出。
- ChatGPT独立レビュー向けの成果物報告をまとめる。

## 各サブタスクの委任フォーマット

オーケストレーターは毎回、Lunaサブエージェントに次を明示する。

- 対象フェーズ、設計文書ID／節
- 実装する具体的な振る舞いと受入条件
- 変更を許可するファイル／範囲
- 依存する既存APIと禁止事項
- 必須のテスト・静的検査
- 完了時に報告する変更内容、検証結果、未検証事項

サブエージェントは1タスクだけ実装し、完了後にオーケストレーターへ返す。**次タスクの自律開始や、追加のサブエージェント委任は禁止**。オーケストレーターがレビュー・検査した後で次のタスクを割り当てる。

## 各フェーズの品質ゲート

各サブタスク／フェーズで次を確認する。

1. 設計書の受入条件を満たし、不要な仕様変更をしていない。
2. 変更対象ファイルが限定され、既存未追跡資産が保全されている。
3. 追加・変更箇所のテストがあり、実際に実行してPASS/FAILを区別できる。
4. lint、typecheck、check:size に問題がない。手書きコードは **500物理行以下かつ32KiB以下**。
5. 変更が共有基盤に及ぶ場合、関連する既存テストも実行する。
6. 権限の追加は必要性を説明できる。過剰なパーミッションを入れない。
7. 入力欄の意図しない消去、誤挿入、誤送信、会話読み込み障害を重大欠陥として扱う。
8. PASS が実測ではない場合に「PASS」と書かない。

不合格なら原因の修正と再検査が完了するまで次フェーズへ進めない。自己レビューは「仕様照合、変更差分、テスト証拠、回帰範囲」を別々に点検し、実装者の自己申告だけに依存しない。

## 自律進行・停止条件

- 設計が確定済みで操作権限内の作業は **Phase 0 から Phase 8 まで順次進めてよい**。毎フェーズでユーザーへの追加承認を求める必要はない。
- 判断を要する未確定仕様は、設計に明記された既定案があればその範囲で進む。決定されていない重要仕様は勝手に補完しない。
- 中断が必要な条件は、仕様の重大な矛盾、破壊的操作が必要、モデル利用の不一致、ユーザーの権限承認が必要、テストで重大な障害が解消できない場合。
- Git操作（add/commit/push）や本番デプロイ、Chromeの手動操作が必要になった場合、**その操作だけを保留**し、それ以外の作業は安全に進められる範囲で継続する。
- 長時間作業ではフェーズ完了ごとに簡潔な進捗を残す。状態が続かなくなった場合の再開位置を明示する。
