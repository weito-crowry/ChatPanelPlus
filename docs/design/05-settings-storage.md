# 設定スキーマ・保存・初期化仕様

- 文書ID: CPP-DESIGN-05
- 状態: 初版
- 依存: 00-architecture.md、03-prompt-actions.md、04-tabs-layout.md
- 基準: 現行 src/shared/settings.ts の schemaVersion: 1、将来の Chrome storage.local 利用
- 目的: UI の全カスタマイズを安全に保存・復元し、デフォルト値と既存設定を保護する。

## 1. 保存対象と不変条件

以下のユーザー要求はすべてサポート対象:
- ボタンの表示／非表示
- ボタンの並び順変更
- ボタン文言の変更
- ボタン色の変更
- タブ順の変更
- タブの表示／非表示
- kind=insert の定型文本文の編集
- 既定レイアウトへの初期化

追加で、選択中タブと最小化状態を保存する。設定のエクスポート・インポートにも対応する。ChatGPT 会話本文、入力欄内容、クリップボード履歴、認証情報は保存・出力しない。

デフォルト UI 定義は 03/04 を正本とし、実装側では共有の不変データを持つ。ユーザー変更は差分・上書きとして扱い、元の定義を直接上書きしない。

## 2. 論理モデル（実装型名は別途確定）

- ConfigRoot:
  - schemaVersion: number
  - buttonOverrides: 安定 buttonId をキーにしたオブジェクト
  - tabOverrides: 安定 tabId をキーにしたオブジェクト
  - buttonOrder: 既定グループ／各タブ単位の安定 ID 配列
  - tabOrder: 安定 tabId 配列
  - answerCompletionSoundEnabled?: 回答完了音の有効状態。省略時は無効
- ButtonOverride:
  - visible?: boolean
  - label?: string
  - color?: string
  - text?: string（kind=insert のみ有効）
- TabOverride:
  - visible?: boolean
- ViewState:
  - selectedTabId: string | null
  - minimized: boolean
- StorageEnvelope: config と viewState を別のキーで保存する。頻繁なタブ選択更新による設定全体の上書き事故を避ける。
- 会話統計は設定の StorageEnvelope に含めず、`chatPanelPlus.statistics` 専用キーへ保存する。スキーマと分岐処理は `12-conversation-statistics.md` を参照。

order は同一表示領域内での並び替えを表す。異なるタブ間へのボタン移動や新規ボタン作成は本実装対象外（要別仕様）。

## 3. デフォルト解決と状態遷移

- 初回利用: Storage に設定値がなければ 03/04 の初期データだけで表示できる。保存書き込みが失敗してもデフォルト UI は動作する。
- 解決: デフォルト構造へ検証済みオーバーライドを投影し、非表示や順序を反映する。UI は解決済みデータだけを使う。
- 保存: Options で変更された有効なフィールドだけを更新する。未変更の設定値と未認識の将来拡張データを破壊しない方針。
- 復元: 不正なタブ選択 ID は可視タブの左端へフォールバック。タブを全部隠した場合は null としてタブ列を表示しない。
- リセット: デフォルトレイアウト復元では、ボタン/タブの表示、順序、ラベル、色、定型文を完全に初期値へ戻す。選択タブはその時点の左端可視タブ、最小化は展開へ戻す。
- 「初期化」の対象外: ChatGPT の未送信入力、会話、他の拡張機能、サイトの既存設定、旧 Tampermonkey 保存値。
- インポート: 読込完了時の選択タブと最小化状態の扱いは UI で明示する。既定はインポートされた config を適用し、ビュー状態は妥当性に応じて保持／フォールバックする。

## 4. 保存方式・同期

- 現行 Manifest の storage 権限を使い、chrome.storage.local を利用する。会話統計のための追加権限は求めない。
- Content Script と Options は shared のバリデータ・設定 Repository API を共用する。
- 読み込み時に例外があれば初期表示を継続し、永続化失敗はエラーを通知する。
- chrome.storage.onChanged 等で変更を購読し、設定画面の保存結果が開いている ChatGPT パネルに反映されるようにする。
- Service Worker を経由しなくても chrome.storage API で扱える設定は、バックグラウンドに二重キャッシュしない。
- Storage 全体を無条件に上書きするのではなく、最新値に対してフィールド単位で変更を合成する。並行編集時に古い Options 画面の全値で後書きしてしまうリスクをテストする。
- 同時書込の厳密な競合解決（比較交換がない API）は制約として明記し、シリアライズ可能な範囲で衝突を抑制する。
- `chatPanelPlus.config.write` の Web Lock は、同じ Lock Manager を共有する保存呼び出しだけを直列化する。`navigator.locks` がない場合や異なる Lock Manager で動く呼び出し間では直列化を保証しない。現在 `saveSettings` を呼ぶのは Options、Content Script は `saveViewState` のみである。
- Lock なしの逐次保存では最新値への dirty field 合成と競合検出が働くが、複数の保存処理が同じ最新値を同時に読み取ると、後の書き込みが先の別 field 更新を失わせる場合がある。Chrome Storage に比較交換操作はないため、この経路の厳密な原子性は保証しない。
- 通常の config 保存と view state 保存は別キーを更新するため互いのキーを上書きしない。レイアウト初期化は `resetViewState` も書くため、同時の minimized／タブ選択更新とは同じ view state キー上で後勝ちになる。
- 会話統計の専用キーは `chatPanelPlus.config` と `chatPanelPlus.viewState` を読み替え・上書きしない。永続化するのは Conversation ID、Turn Key、Assistant Message ID、INPUT/OUTPUT文字数、およびTurn Key順序だけで、本文・ハッシュ・HTML・タイムスタンプは含めない。
- 会話統計の台帳には独立した `schemaVersion` と厳格な形状・ID・数値検証を適用する。破損または未知バージョンを無確認で上書きしない。
- 会話統計の保存は差分を抑えたデバウンス書き込みとし、容量超過などの失敗をUIへ返す。失敗したメモリ値を保存済みとして扱わず、他会話の行を削除しない。

## 5. バリデーション

- JSON を信頼せず、root が通常オブジェクトか、バージョン・配列・辞書・フィールド型が妥当かを検査する。
- ID は既定 UI に存在するものだけ動作対象とし、未知 ID から任意アクションや JavaScript を生成しない。
- label と text はプレーンテキストとして扱い、innerHTML に渡さない。空文字による UI の消失は Options 上で確認・プレビューできるようにする。
- color は元 v7.2 の #RGB / #RRGGBB など安全な CSS 色表記を中心に検証する。入力値が不正な場合は既定色を使うかエラー表示する。
- 順序配列の重複・不明 ID・欠損 ID は決定的に正規化する。新しいバージョンで増えた既定ボタンは一意に挿入する。
- text は実行文字列ではなく、編集欄へ渡す文字列として扱う。定型文本文を送信・ログ保存しない。
- 不正値が一部分に限られるとき、有効な既存設定を全部破棄しない。可能な範囲で有効値を保持し、補修を明示する。

## 6. スキーマとマイグレーション

- src/shared/settings.ts の現行 schemaVersion:1 は実装済みの保存構造を意味しない。既存テストが求めるバージョン表記を確認して段階的に移行する。
- schemaVersion をインクリメントする際は、バージョン別 migrator とテストを準備し、既存有効フィールドを維持する。
- 将来版の設定ファイルや破損した JSON を無確認で上書きしない。読み込み専用・エラー表示など安全な方式を採る。
- v7.2 の localStorage キーは gpt-quick-btns-active-tab（旧版のラベル値を ID に変換）と gpt-quick-btns-minimized。新しい chrome.storage.local に暗黙移行しない。要否と互換性の実測後に独立した移行処理を追加する。
- ID の名称を変更する場合は旧 ID からの対応表とテストを必須とする。単なる表示ラベル変更で ID は変更しない。

## 7. エクスポート・インポート

- エクスポートは、スキーマバージョン付き JSON として設定に必要な値のみ出力する。任意のページ本文・内部機密・クリップボードは含めない。
- インポートはファイル読取 → JSON 解析 → スキーマ検証 → 適用前プレビュー／確認 → 一括保存 → パネル反映とする。
- 不正 JSON／未知バージョン／不正アクション値は理由を示して拒否し、現在の設定を維持する。
- ファイル由来のラベル・プロンプト本文を HTML としてレンダリングしない。
- エクスポート→初期化→インポートで設定値と既定レイアウトの差分が再現されること。
- 暗黙の自動クラウド同期は実装しない。保存はローカル優先。

## 8. 受入条件

- 指定された8項目が編集・保存・再読み込み後の復元・デフォルト復帰に対応する。
- 全20ボタン・5タブの既定値が設定なしで再現される。
- Options の変更が開いているパネルへ反映する。
- タブ選択と最小化は設定変更と独立して永続化される。
- 設定のスキーマバージョン移行・欠損・未知ID・重複順序・不正色・空設定で例外を起こさない。
- エクスポート・インポートが往復可能で、適用失敗時に既存設定が失われない。
- ChatGPT の入力本文、クリップボード、他の拡張機能の保存データに手を触れない。
