# ChatPanelPlus 全体アーキテクチャ設計

- 文書ID: CPP-DESIGN-00
- 状態: 初版（設計レビュー対象。実装承認ではない）
- 基準日: 2026-10-21
- 対象: 既存 Chrome MV3 拡張 ChatPanelPlus v0.1.5 からの機能移植
- 移植元: ChatGPT 定型ボタン（UI-tree, tabs, clipboard-fallback）v7.2
- 関連: AGENTS.md、README.md、今後作成する CPP-DESIGN-01 以降

## 1. 目的と優先順位

Tampermonkey v7.2 の既存操作を、React 19／TypeScript 6／Vite 8／Chrome Manifest V3 の保守可能な構成に移植する。旧コードの無条件な逐語移植ではなく、機能・既定レイアウト・利用時の挙動を互換要件とする。

優先順位は (1) ChatGPT の通常機能を壊さない、(2) ユーザーの未送信入力を壊さない、(3) v7.2 の操作互換、(4) 保守性、(5) 設定によるカスタマイズ、(6) 将来拡張、の順とする。品質のために存在しない機能を追加したり、未確認の内部 API に依存したりしない。

## 2. 確認済み現状と対象範囲

### 2.1 現行の事実

- v0.1.5 では Content Script、React パネル、Shadow DOM、Service Worker、Options 表示と OPEN_OPTIONS メッセージ通信が動作確認済み。
- 現行ソースにプロンプト編集、定型ボタン、状態保存の完成実装はない。共有設定スキーマは schemaVersion: 1 が中心である。
- main は初回コミット前（unborn branch）、既存ファイルは未追跡。git diff だけで既存資産を判断しない。
- Chrome 登録済みロード元 [USER_WORKSPACE_ROOT]\Documents\src\codexapp\ChatPanelPlus-Content-Probe-20261021 は保全対象とする。通常の直接編集・手動コピー・移動・改名・削除・再登録は禁止する。ユーザーが明示的に承認した場合に限り、検証とバックアップを経由する pnpm deploy:chrome による成果物更新を許可する。承認なしの deploy は禁止し、Chrome 拡張の再読み込みはユーザーが別途手動で行う。通常の開発はリポジトリ [USER_WORKSPACE_ROOT]\Documents\src\codexapp\ChatPanelPlus で行う。

### 2.2 今回の実装対象

- v7.2 の常時表示ボタン 4 個、タブ 5 個、各タブ内の定型ボタンと文字列、最小化・復帰、タブ切替、状態保持。
- 入力欄の検出、選択範囲・カーソルの保持、先頭への定型文挿入、現在位置へのクリップボード挿入、クリア、JST 日時挿入。
- クリップボード読取失敗時の手動貼り付けと操作エラー通知。
- ChatGPT の SPA 遷移や Composer 再構築時にパネルを復元する機構。
- ボタン表示・非表示、ボタン順序・ラベル・色・定型文本文、タブ表示・非表示と順序の設定。
- デフォルトレイアウト復元、設定の永続化、インポート・エクスポート、Options による編集。
- Conversation ID 単位の会話統計（Turns、INPUT/OUTPUT/総文字数）。新規発言は増分集計し、過去発言はユーザー操作による再集計で取得する。
- 元のスクリーンショットと v7.2 CSS に可能な限り近い既定外観（React／Shadow DOM 向けに内部 CSS は整理可）。

### 2.3 今回の対象外

- ChatGPT API や非公開エンドポイントを使う会話取得・送信、バックグラウンドでの自動送信。
- 通知、Codex 連携の実機能。将来の拡張境界だけを考慮し、先行して実装しない。
- 既存4操作にない新しいボタン動作・カスタムスクリプト実行機能。既存動作を選ぶユーザー作成ボタンは CPP-DESIGN-15 の別仕様で扱う。
- 旧 ID の 429 障害原因究明・旧 ID への復帰。原因は未確定のためコード不具合や OpenAI 側制限と断定しない。

## 3. 設計原則と責務境界

- UI と ChatGPT DOM 操作を分離する。React コンポーネント内に DOM セレクタ、Range 操作、Clipboard API の実装を埋め込まない。
- 定型アクションの公開契約は「入力欄の内容を変更するが送信しない」。送信ボタンを押さず、Enter キーを合成しない。
- 既定レイアウトは不変の基準データとし、ユーザー設定は別に保持する。リセットにより基準状態へ戻せること。
- Chrome 拡張の Content Script を唯一のページ編集主体とし、Service Worker を入力編集の経由点にしない。
- 権限は必要な機能の導入時に限定して宣言する。現行 Manifest の `clipboardRead` と `storage` で既存機能とローカル統計保存を賄い、追加権限を求めない。
- 例外、既知の未対応、ユーザー側の確認が必要な操作は表示・記録し、成功を偽装しない。
- ページ本文やクリップボードの内容を操作上必要な一時処理以外に保存・ログ出力しない。
- 実装は各手書きソース 500 物理行以下・32 KiB 以下、追加依存を最小限とする。

## 4. 論理コンポーネント

以下は責務の設計であり、具体的なファイル名・公開 API は後続の設計書で確定する。現行の src/content/main.tsx、src/content/Panel.tsx、src/background.ts、src/shared/settings.ts、options/src/OptionsPage.tsx は可能な限り再利用する。

### 4.1 Content Script ブートストラップ・ライフサイクル

- ChatGPT ページで起動し、パネル用ホスト・Shadow Root・React ルートを重複生成せずに確保する。
- Composer の位置・可視性・接続状態を監視し、SPA 遷移・DOM 再生成に伴うパネルの切断・位置ずれに復帰する。
- DOM 監視は軽量化し、監視由来の自己再描画ループを避ける。終了時には observer、イベント登録、タイマー等を適切に解放する。
- UI を再マウントしても未送信入力欄そのものを書き換えない。可能であれば表示状態を保持する。

### 4.2 React パネル（プレゼンテーション層）

- 既定 UI ツリーと解決済み設定を受け取り、常時表示群、タブ群、ボタン群、最小化トグル、設定導線を描画する。
- UI イベントを意味のあるアクション要求へ変換するだけで、入力欄内部は直接編集しない。
- タブ選択・最小化の状態表示を管理し、永続化インターフェースを通して保存する。
- 画像の既定レイアウト・配色・ボタンサイズ・タブ形状を優先して再現し、画面幅やダークモードに対応する。

### 4.3 アクション・ディスパッチャー

- 識別子と型の定義済みアクションだけを実行し、表示ラベルを処理の根拠にしない。
- insert（定型文を先頭に追加）、insert-jst、paste-at-selection、clear の責務を分離する。
- 処理を 1 回のユーザー操作に対して 1 回のみ実行する。非同期の失敗は握り潰さず、ユーザーに通知する。
- 任意 JavaScript の設定実行や HTML の無検証挿入は行わない。

### 4.4 ChatGPT エディタ・アダプター

- Composer 内の実際の編集可能要素を探索し、返信編集・別フォームを誤選択しない。
- ProseMirror／Lexical 等の DOM 差異を吸収し、編集対象の可視性、接続、有効性を毎操作で確認する。
- 先頭挿入とカーソル位置挿入を区別し、未送信本文の全文再構築を行わない。空白・改行・選択範囲の契約は独立仕様で明記する。
- クリップボード取得開始時に保存した Composer Element と挿入直前の最新 Composer Element が異なる場合は、同一会話で DOM だけが再生成された場合も含め、自動挿入を中止して明示的な再試行を促す。新しい Composer へのフォールバック挿入はしない。
- 合成 input 等のフォールバックは「ChatGPT が実際に入力として認識したか」を実機で検証する。

### 4.5 クリップボード・ユーザー通知

- 読取を試みるのは明示的な「コピペ」操作時のみ。権限拒否・空文字などは手動貼り付けダイアログへ切り替える。
- クリック前のカーソル／選択状態を可能な範囲で保存し、貼付位置を復元する。復元不能な場合は仕様に定めた安全なフォールバックとする。
- トースト／ダイアログを React 側の UI 責務として分離する。許可ダイアログの扱いは Chrome 実機で確認する。

### 4.6 設定・既定レイアウト・永続化

- shared 層にデフォルト UI 定義、スキーマ、正規化／検証／マイグレーションを置き、Options と Content Script で共用する。
- 保存先は chrome.storage.local を基本とし、設定の読込・変更・保存・通知を一つの抽象化に集約する。
- 変更対象はボタンの visible、order、label、color、text と、タブの visible、order、および選択状態・最小化状態。
- 未知の識別子、欠損値、壊れた設定、旧スキーマ、バージョン違いを扱う規則を後続の設定仕様で定義する。
- インポートは形式検証後に適用、エクスポートは設定データのみ。会話本文・クリップボード内容を含めない。
- Tampermonkey 版 localStorage のキーを新しい設定と同一視しない。旧値自動移行は別途動作検証を前提とし、未確認のまま有効化しない。

### 4.7 Options と Service Worker

- Options は共有スキーマに基づく編集画面とし、設定の表示・保存・復元・JSON 入出力を提供する。
- Service Worker は既存の OPEN_OPTIONS を維持し、拡張権限が必要な操作だけに責務を限定する。単純な入力欄操作やパネル再描画の中継はしない。
- Options 変更時は Storage 変更通知等で開いている ChatGPT パネルへ反映し、ページ更新を必須にしないことを目標とする。

### 4.8 会話統計

- Conversation ID ごとの統計台帳を `chrome.storage.local` の専用キーへ保存する。設定・ビュー状態とは分離し、ID と文字数だけを永続化する。
- Content Script は現在の ChatGPT DOM の属性から Turn Key と Assistant Message ID を識別する。本文は新規発言、選択中回答の再生成、ユーザー操作による再集計時に必要な領域だけ読む。
- ページ初回表示・スクロールで初めてDOMに現れた過去ターンは、自動で文字数を計上しない。手動再集計で現在DOMにあるターンを再走査する。
- 分岐に属すると確認できない保存済み行は集計せず、台帳行は残したまま部分集計として示す。本文・ハッシュ・HTML は保存しない。
- DOM識別、分岐処理、プライバシー、制限は `12-conversation-statistics.md` を正本とする。

## 5. データフロー

- 起動: Content Script → ホスト/Shadow DOM → React 表示 → 永続化設定読込 → 正規化済み UI を描画。
- ボタン: ユーザークリック → UI → アクション・ディスパッチャー → エディタ・アダプター／クリップボード → 結果を UI 通知。ネットワーク経由の送信処理なし。
- 設定: Options 入力 → スキーマ検証 → chrome.storage.local → 変更通知 → パネルの再描画。
- 会話統計: ChatGPT DOM → Turn Key/Assistant ID の増分識別と必要箇所の文字数計測 → 専用台帳をローカル保存 → Shadow DOM パネルに集計値を表示。
- タブ: ユーザー選択 → 表示状態更新 → 保存。復元する選択タブが表示対象にない場合は左端の表示タブへ戻す。
- 設定ボタン: React → OPEN_OPTIONS → Service Worker → chrome.runtime.openOptionsPage。

## 6. 既定 UI・状態の不変条件

- 初期レイアウトは添付スクリーンショットと v7.2 の UI ツリーを基準にする。常時表示は「現在時刻」「コピペ」「クリア」「雑談」の順。
- タブ初期順は「指示」「会話制御」「壁打ち」「二択」「四択」。**初回選択の規則はラベル『指示』への固定参照ではなく、左端の表示タブ**。
- 明示的にユーザーが切り替えたタブは保存して復元する。保存対象が非表示・不存在なら現在の左端の表示タブへフォールバックする。
- 全タブを非表示にする操作の詳細は設定仕様で定義する。今回の段階で暗黙に UI を壊す実装にしない。
- ボタン初期値は v7.2 の ID、色、表示文字、テキスト本文を無変換で保全する。長文の「引継ぎ」「壁打ち開始」も全文をソース定義へ移す。
- v7.2 と同じく、定型文は入力欄先頭へ、コピペは選択位置へ挿入し、送信しない。
- 既定外観は配置、白地の角丸パネル、上辺中央トグル、色付き丸ボタン、タブとその下段内容をできる限り再現する。ダークモード・レスポンシブ対応は視覚互換を壊さない範囲で調整する。
- 右下の「ChatPanelPlus 設定」導線は現行拡張側の要素であり、v7.2 の UI ツリーとは別要素として扱う。最終的な統合・表示位置は UI 仕様で決める。
- 設定のデフォルト復元は既定ボタン/タブを初期値へ戻し、ユーザー作成ボタンは保持して既定ボタンの後ろへ置く。

## 7. MV3・実行コンテキスト

- Content Script はページ DOM を操作するが、ページ内スクリプトの内部オブジェクトを利用できると仮定しない。DOM で検証できる公開挙動を利用する。
- React は Shadow Root 内に描画し、ChatGPT 本体の CSS・DOM への影響を局所化する。ただし既定パネルの配置は Composer を参照するので監視機構と分離する。
- `storage` 権限は現行 Manifest に含まれ、設定と統計の `chrome.storage.local` 保存に使う。Clipboard API の成功を拡張権限宣言だけで保証せず、ユーザー操作・実機環境の制約を検証する。
- CSP、拡張分離環境、Service Worker の停止／再起動を前提とし、バックグラウンドに保持した一時状態を必須にしない。
- 原則 chatgpt.com 上で動作し、その他ドメインを推測で追加しない。

## 9. 実装順序と検証ゲート

1. 現行ソース・未追跡資産を保全し、初回 Git ベースラインの作成はユーザー承認後に実施する。
2. 既定 UI 定義・設定型の土台とエディタ・アダプターを確立する。
3. 単一ボタンで編集動作を検証し、以後は機能単位で実装・試験・自己レビューする。
4. タブ・最小化・クリップボード・設定／Options を順次統合する。
5. 全機能の静的解析、型検査、サイズ制限、テスト、ビルドに合格させる。
6. 正式 Chrome ロード元への deploy は独立した承認後に限り、Chrome 拡張の再読み込みと実機確認はユーザーが行う。
7. 最終受入は ChatGPT が仕様との整合性、回帰、未検証事項を独立レビューする。

現行コマンドは pnpm check:size、pnpm lint、pnpm typecheck、pnpm test、pnpm build、pnpm deploy:chrome。pnpm test はビルドを先行するため、検査コマンドにも成果物の書換えがあることを認識する。設計書作成だけの段階では実行不要。

## 10. 未確定事項・後続設計で決めること

- 他タブへのボタン移動は初版の対象外とし、将来の拡張候補として別仕様で判断する。初版の並び替えは常時表示グループ内または同一タブ内に限定する。
- 全タブを非表示とする設定の UX とアクティブタブの表現。
- v7.2 にない Options 編集 UX の詳細、設定保存タイミング、誤操作防止、インポート時の衝突解決。
- 初期 UI と現行右下設定導線を最終的にどう共存させるか。
- ChatGPT の現行 DOM・各入力欄モードで実際に利用可能な挿入操作を実機確認する（Composer Element が差し替わった場合は 01/07 の中止・再試行規則を適用する）。
- v7.2 の保存済みタブ・最小化状態の移行要否と検証方法。

これらは未確定のまま実装しない。必要な場面でユーザー判断が必要な場合は、対象の機能別設計段階で提示する。
