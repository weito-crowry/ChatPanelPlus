# Options 設定画面設計

- 文書ID: CPP-DESIGN-06
- 状態: 初版
- 依存: 00-architecture.md、03-prompt-actions.md、04-tabs-layout.md、05-settings-storage.md
- 現状: Options の設定編集、JSON入出力、カスタムボタン作成・編集は実装済み。詳細は `15-custom-buttons.md` を参照。

## 1. 目的

追加した設定画面から、既定20ボタンと5タブの外観・可視性・順序・定型文を編集し、既存操作を使うユーザー作成ボタンを追加・編集できるようにする。元 v7.2 の UI と動作をデフォルトにし、編集を一度もしなくてもパネルを使える状態を保つ。追加仕様は `15-custom-buttons.md` を参照。

## 2. ページ構成

- ページ上部: タイトル、保存状態、操作ガイド。
- 「常時表示ボタン」: 4 個の操作ボタンの表示状態、順序、ラベル、色を編集。
- 「タブ構成」: 指示、会話制御、壁打ち、二択、四択の表示状態と並び順を編集。
- 「タブ内ボタン」: 選択タブのボタン表示、順序、ラベル、色、kind=insert の定型文を編集。
- 各ボタン群: 追加先の群にユーザー作成ボタンを追加し、既存操作、ラベル、色、必要な定型文本文を設定。
- 「通知」: ChatGPT回答完了音の有効・無効を編集。初期値は無効。
- 「レイアウト操作」: 既定値に戻す、設定を書き出す、JSON 設定を読み込む。
- 必要なら現在の編集対象と保存済み値の差分を確認できるようにする。背景 ChatGPT の会話本文は取り込まない。

v7.2 の「常時表示」と「タブ」を明確に区別し、別タブへの移動機能を未確定のまま暗黙に増やさない。

## 3. 編集 UI と操作

- 表示/非表示: 各ボタン・タブ単位のスイッチまたはチェックボックス。隠した設定対象も Options 一覧には残し、再表示できる。
- 並び替え: マウスドラッグに加え、キーボードでも上下移動できるコントロールを提供する。ドラッグ未対応環境でも必ず順序を編集できる。
- ボタン名: 任意のプレーンテキスト。内部 ID は別表示とし編集不可。
- ボタン色: カラーピッカーと必要に応じて Hex 入力。v7.2 の #888 等を有効な色として扱い、表示時の変換で原色を失わない。
- 定型文: 複数行テキストエリア、実際の改行・前後空白を保持。既定ボタンの action は固定し、カスタムボタンは既存4操作の間で変更できる。
- タブ名: 今回の明示要件にないため初版では既定ラベル固定。将来の拡張余地を残す。
- 全タブ非表示を選んでも常時表示ボタンと Options は使える。利用者が再表示できることを明示する。
- ID の重複、無効な色、無効なデータ型などはその場で提示し、破損値を保存しない。

## 4. 保存 UX（本仕様の提案既定）

- Options は保存済み設定のコピーを編集用ドラフトとして読み込む。
- 変更は画面内プレビューへ即時反映するが、他の ChatGPT パネルへは「保存」実行後に反映する。
- 「保存」押下で全編集値を一括検証し、成功した場合だけ chrome.storage.local の設定を更新する。
- 保存前にページを閉じると未保存の変更が失われる可能性を適切に知らせる。
- 他タブで設定が更新された場合は古いドラフトの無条件上書きを避け、競合・再読込・破棄を利用者へ提示する。
- 保存成功は実際の API 成功が確認できてから表示する。失敗時は現在のドラフトを保ち、再試行できる。
- 保存済み設定を修正してもメインパネルは再読み込み不要で追従することを目標とする。

## 5. レイアウト初期化

- 「デフォルトに戻す」は誤操作防止の確認を伴う。
- 初期化する対象は全20個の既定ボタンの表示、順序、ラベル、色、定型文と、全5タブの表示・順序、選択タブ・最小化の状態。ユーザー作成ボタンは保持し、各群の末尾へ配置する。
- デフォルトは 03/04 の値。初期化後の選択タブは左端可視タブ、パネルは展開状態。
- ChatGPT 入力内容、会話内容、他拡張や Tampermonkey の localStorage 値は一切消去しない。
- リセット結果を確定するまでは元の保存設定を保護する。画面プレビューだけの初期化か即適用かは UI 上で明確にする。既定ではドラフトへ初期化し、「保存」で確定する。

## 6. JSON エクスポート・インポート

- 書出: 設定スキーマバージョンと UI カスタマイズ値を含む JSON。ローカルファイルへ保存できる。
- 読込: ファイル選択 → テキスト取得 → JSON パース → バージョン検証 → 設定値検証 → プレビュー → 適用確認。
- インポート失敗時に保存済み設定は変更しない。
- プレビューには保存済み／適用後のカスタムボタン数を表示する。旧 v1 JSON（`customButtons` 欠落）は保存済み定義を引き継ぐ。明示JSONで削除が生じるときは削除予定IDを表示し、ドラフト適用前に確認する。
- 読込ファイルのプレーンテキスト部分を HTML として解釈しない。埋込スクリプトや追加アクションを実行しない。
- 有効な設定が読めた場合でも、保存はユーザーの明示操作を待つ方式に統一する。
- エクスポート→初期化→インポートの往復で設定値を再現できる。
- JSON にタブ選択・最小化状態を含むかは利用者に分かるよう明記し、初版では設定本体を中心に書き出す。ビュー状態の勝手な変更を避ける。

## 7. 見た目・アクセシビリティ

- v0.1.5 の Options 初期UIから拡張し、全設定対象をグループ化して迷わず編集できる。
- ボタンの背景色だけでなく文字ラベルと配置も表示し、パネルの標準レイアウトに近いプレビューを持つ。
- 通常のラベル、説明、フォーカス可視性を備え、ドラッグ操作だけに依存しない。
- 定型文本文や UI 文言は長い場合でも改行・選択・編集可能とし、スクロールで操作できる。
- 設定画面から Chrome ページの直接 DOM 操作をしない。保存された設定データを Content Script が描画する。

## 8. 受入条件

- 指定8項目を、ユーザーが Options だけで変更・保存・再読込できる。
- 20ボタン・5タブの初期値が表示され、非表示対象も編集画面から再表示できる。
- 回答完了音の設定を有効・無効にして保存・再読込できる。
- ボタン順とタブ順がパネルの表示順に反映される。
- 「引継ぎ」「壁打ち開始」を含む複数行定型文の空白・改行が保持される。
- 色変更や文言変更で action や ID が変わらない。
- 既存4操作を選んだユーザー作成ボタンを追加・編集・並べ替え・削除でき、保存後にパネルへ反映される。
- 既定値復元後もユーザー作成ボタンが保持され、削除は個別操作で反映される。
- 保存前の未確定変更が勝手に本番パネルへ適用されず、保存成功後に反映される。
- 初期化、JSON 往復、不正ファイル、保存失敗、複数 Options の競合を検証できる。
- Chrome の登録済み新 ID フォルダを動かさず実装・試験できる。
