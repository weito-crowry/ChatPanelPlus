# カスタムボタン

- 文書ID: CPP-DESIGN-15
- 状態: 設計案（レビュー待ち。実装計画・実装は未開始）
- 依存: 00-architecture.md、03-prompt-actions.md、04-tabs-layout.md、05-settings-storage.md、06-options-page.md、09-testing.md
- 目的: 既定の20ボタンに加え、ユーザーが既存操作から選んだボタンを追加・編集・並べ替え・削除できるようにする。

## 1. 対象範囲

- Optionsの既存グループ（常時表示と5つの既定タブ）に、カスタムボタンを追加できる。
- カスタムボタンごとに、現在サポートしている操作を1種類選ぶ。
- ラベル・色を編集し、定型文挿入では本文も編集する。
- 追加ボタンを既存のパネルに表示し、表示切替・並べ替え・保存・JSON入出力に含める。
- 既定20ボタンと5タブのID・動作・初期順序は維持する。既定ボタンは従来どおり設定できる。
- 既定レイアウトへ戻す操作は既定ボタンとタブを初期化し、ユーザー作成ボタンを保持する。カスタムボタンの削除はそのボタンの削除操作で明示的に行う。

対象外:

- 既存5タブ以外のグループや新規タブの作成。
- 1つのボタンで複数操作を連続実行すること。
- 任意スクリプト、任意JavaScript、現行4操作にない新しい操作種別。
- カスタムボタンを追加後に別グループへ移動すること。追加時に選んだグループで使う。

## 2. 選択可能な操作

カスタムボタンは、次の既存動作のいずれか1つを使う。挿入・貼り付け・クリアの動作契約は `03-prompt-actions.md` と `07-clipboard.md` を再利用し、パネルから自動送信しない。

| 操作 | 表示と編集フィールド | 実行動作 |
| --- | --- | --- |
| 定型文を挿入 | ラベル・色・本文 | Composerの先頭に本文を挿入 |
| 現在時刻を挿入 | ラベル・色 | 既定のJST日時文字列をComposerの先頭に挿入 |
| クリップボードを貼り付け | ラベル・色 | 既存の貼り付け処理を使い、現在の選択位置へ挿入 |
| 入力欄をクリア | ラベル・色 | 既存のクリア処理でComposerの未送信内容を消去 |

新規作成時の初期表示は追加先のグループ末尾、表示ONとする。ラベルは選択操作に対応する既定名を初期値として入れ、ユーザーが編集できるようにする。色は既存パレットの既定色を初期値にする。

## 3. Optionsの編集フロー

- Optionsの常時表示・各タブのボタン一覧に「ボタンを追加」操作を置く。押したグループに新規ボタンを追加する。
- 追加フォームで操作種別、ラベル、色を指定する。定型文挿入を選んだ場合だけ本文欄を表示する。
- 新規ボタンはドラフトへ追加し、既存のプレビューで確認できる。パネルへの反映は既存Optionsと同じく「保存」後とする。
- 保存後は現在のパネルと開いている他のChatGPTパネルへ、既存設定通知経路で反映する。
- 一覧からカスタムボタンを編集、非表示、同じグループ内で並べ替え、削除できる。既定ボタンの編集・削除操作は従来仕様を維持する。
- 削除はOptionsのドラフトだけに反映し、「保存」前なら取り消せる。
- 既定レイアウト復元では既定ボタンの設定と既定順序を戻し、カスタムボタンをグループ末尾に保つ。既定ボタンの設定変更、カスタムボタンの削除、タブ変更、ビュー状態のリセットを混同しない。

## 4. 設定データ

`chatPanelPlus.config` に任意の `customButtons` レコードを追加する。キーは作成時に生成して以後変更しない `custom-` 接頭辞付きIDとし、ラベルや表示順からIDを作らない。定義値は `groupId`、`kind`、操作種別、ラベル、色、表示状態、必要な場合のみ本文を持つ。

概念型:

- `customButtons?: Record<CustomButtonId, CustomButtonDefinition>`
- `CustomButtonDefinition`: `groupId: ButtonGroupId`, `label: string`, `color: string`, `visible: boolean`, および既定ボタンと同じ `kind/action/text` の判別可能な操作フィールド。
- `ButtonGroupId`: 常時表示または既存5タブのいずれか。
- `buttonOrder[groupId]`: 既定IDと、そのグループに属するカスタムIDを同じ順序配列に含める。

現行設定と同じ `schemaVersion: 1` の追加フィールドとして扱い、既存設定で `customButtons` が欠ける場合は空として解決する。既定20ボタンの設定をカスタム定義へ複製・変換しない。JSON export/importにもこのフィールドを含める。

## 5. 解決・保存・入力検証

- 共有設定バリデータが追加ボタンを検査し、既定UI定義とカスタム定義を統合して、既存Panelが使う解決済みボタン一覧を返す。
- IDは一意で安定していることを検査し、既定IDとの衝突を拒否する。
- groupIdは既存6グループに限る。buttonOrder上のカスタムIDも、定義されたgroupIdの順序配列にだけ受け入れる。
- kind/action/textの組み合わせを既存4操作に照らして検査する。定型文挿入だけが本文を持ち、他の3操作に任意本文や未知actionを認めない。
- label/textは既存ボタンと同じくプレーンテキストとして描画する。HTMLやスクリプトとして解釈しない。不正色を含む不正なカスタム定義は検証エラーとし、設定ファイルの適用時は既存設定とドラフトを維持する。
- カスタムIDの設定はID単位で保存競合を判定し、同じIDを異なるOptionsドラフトが更新・削除した場合は既存Repositoryの競合表示へ返す。グループ内の並び順は既存 `buttonOrder` の競合処理を使う。
- 追加・削除・並べ替えの保存が失敗した場合、成功表示やパネル反映を行わずドラフトを保持する。

## 6. JSON入出力・既定値復元

- exportはカスタム定義とグループごとの順序を含め、importは既存のプレビュー・確認・保存フローを再利用する。
- import時はカスタムID重複、既定ID衝突、不明グループ、不正操作、operation/actionと本文フィールドの不一致を検証する。
- 不正な設定ファイルは適用せず、既存保存値と編集中のドラフトを維持する。
- export → reset defaults → import でカスタム定義と順序が戻る。
- 「既定値に戻す」は既定20ボタンとタブを初期化する操作であり、カスタムボタンを削除しない。

## 7. 検証・受入条件

- 既存schemaVersion 1設定にカスタム定義がなくても、既定20ボタン・5タブ・現在の設定が従来どおり表示される。
- 4種類それぞれのカスタムボタンを追加し、保存・再読込後にパネルへ正しい操作で表示できる。
- ラベル、色、定型文本文、表示切替、同一グループ内の順序が保存・再読込・設定通知後に維持される。
- 追加先のグループにボタンが現れ、別グループへ誤表示されない。各操作は既定ボタンと同じ実行処理を使い、自動送信しない。
- カスタムボタンの削除は保存後に反映され、保存前のドラフトでは元に戻せる。
- 既定値復元後もカスタムボタンが残り、既定ボタンとタブだけが初期値に戻る。
- JSON export/importの往復でカスタム定義と順序が保たれ、不正JSON/不正定義では現在の設定が変わらない。
- ID衝突、不明groupId、未知のaction/kind、不正色、本文フィールド不一致、設定競合を自動テストする。
- `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm check:size` を実施する。Chrome実機のOptions操作と複数タブ反映は自動テストから分けて記録する。
