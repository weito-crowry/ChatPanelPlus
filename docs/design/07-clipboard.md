# クリップボード操作・手動貼り付け設計

- 文書ID: CPP-DESIGN-07
- 状態: 初版
- 依存: 01-editor-adapter.md、02-panel-ui.md、03-prompt-actions.md
- 移植元: v7.2 の readClipboardTextWithFallback、openManualPasteDialog、rememberPasteSelection、pasteAtCaret

## 1. 目的

「コピペ」ボタンでユーザーが現在のクリップボードからテキストを取得し、ChatGPT の編集欄のカーソル・選択位置へ挿入する。読み取りが禁止された場合は手動貼り付けダイアログを使い、処理に失敗しても未送信入力を破壊しない。

## 2. 操作フロー

1. ユーザーがコピペボタンを押す直前に Composer Element 参照と Range・選択状態のスナップショットを一時的に保持する。
2. クリックのユーザー操作を契機に navigator.clipboard.readText() を試す。
3. 成功してテキストがある場合、CRLF を LF にそろえてエディタアダプターへ渡す。
4. API が利用できない、権限拒否、取得失敗、空文字の場合は通知を表示し手動貼り付けダイアログへ移る。
5. 手動ダイアログで「挿入」を押すと、その textarea に入力された内容をアダプターへ渡す。キャンセル／空文字なら何もしない。
6. 挿入直前に最新 Composer Element を再検出して取得開始時の参照と比較する。異なる場合（同じ会話での DOM 再生成を含む）は自動挿入を中止し、composer-changed エラーを通知して明示的な再試行を促す。新しい Composer へは挿入しない。同一 Element の場合は保存 Range が有効ならその位置へ、無効なら現在の有効 Range、なければ末尾へ挿入する。
7. 成功／失敗を確定し、一時的な本文・Range を解放する。自動送信しない。

v7.2 は readText() の前に document.hasFocus() を確認し window.focus() と次タスク待機を試みる。移植ではこれを無条件の解決策とせず、Chrome 拡張の実際の権限・ユーザーアクティベーションを確認する。

## 3. React・Shadow DOM のイベント設計

- ボタンがクリックによりフォーカスを奪う前に編集欄の Range を保持する。pointerdown/mousedown とキーボード操作の順序差をテストする。
- Range はページ DOM を参照するため、Options や Service Worker へ送らない。ローカルの一時メモリに留める。
- readText() または手動ダイアログの待機中に Composer Element が差し替わった場合は、挿入直前の同一性確認で処理を中止し、新しい Composer へ書き込まずエラー通知する。
- 連打・ダイアログ多重表示・複数の readText 完了順競合を制御する。二重貼り付けを起こさない。
- クリップボード読取が非同期であるため、選択範囲の接続状態を挿入直前に再検証する。
- デバッグ用計測はテスト時だけ明示的に有効化できるようにし、クリック開始、権限状態確認、Clipboard API 読取、手動ダイアログ待機、エディタ操作、全体完了までの各所要時間を測定する。結果状態は Clipboard API の成功／拒否・失敗／空文字、手動入力／取消、composer-changed、エディタ成功／失敗を識別する。権限関連処理・API読取・エディタ処理の時間を区別し、未実測の遅延閾値は設けない。計測は既定で無効とし、通常操作に不要な負荷を加えない。メッセージ本文・クリップボード内容をログ・永続化・送信せず、計測値も永続化・送信しない。

## 4. 手動ダイアログ仕様

- タイトル: 「クリップボードの読み取りがブロックされました」
- 説明: ユーザーが Ctrl+V（macOS相当表記が必要なら併記）で貼り付けできる旨を案内。
- 入力: 複数行 textarea、初期値は空、改行・前後空白を維持。
- 操作: 「挿入」「キャンセル」。背景クリックや Escape でキャンセル可能。勝手な Enter 送信は行わない。
- 起動時に textarea へフォーカスし、閉じると可能な範囲で本来の操作箇所へ戻す。モーダルのフォーカス移動と Tab 操作を確認する。
- CSS と DOM は React パネルの所有領域に閉じ、ChatGPT ページへ大域的な style を追加しない。
- 手動入力したテキストは保存・テレメトリー送信・ログ出力しない。

## 5. 権限・データ保護

- Clipboard API 成功を Manifest 権限設定だけで保証しない。ユーザー操作の有無、フォーカス状態、Chrome の許可と実機で確認する。
- 追加権限は機能実装時に必要性を説明して導入。不要な host_permissions や全サイトアクセスを加えない。
- クリップボード内容や手動貼り付け全文をログへ書かない。ダイアログを閉じたら一時データを破棄する。
- テキストはプレーンテキストとして挿入し、HTML として評価しない。
- その他のアクションがクリップボードを勝手に読み取る経路を設けない。

## 6. 受入条件

- 既存文章の先頭・途中・末尾、選択範囲上のそれぞれで意図どおり挿入される。
- 貼付位置の保持はボタンフォーカス、タブ切替、Shadow DOM 境界で壊れない。
- CRLF と複数改行、全角文字、空白を保持して挿入できる。
- 権限拒否時は手動入力へ移り、キャンセル時は Composer 無変更。
- ダイアログ連打や空文字による重複挿入がない。
- 読取待機中の画面遷移または Composer 再生成で開始時と挿入直前の Composer Element が異なる場合、自動挿入を中止してエラー通知し、明示的な再試行を促す。新しい Composer は変更しない。
- Composer Element が同一で保存 Range が無効なら、現在の有効な Range を使い、なければ末尾へ挿入する。
- テスト時に計測を有効化し、定めた各段階の所要時間と結果状態を確認する。計測にメッセージ本文・クリップボード内容を含めない。
- Chrome 実機上で挿入後の本文がモデルに反映され、通常の送信操作でその文章を使える。ただし拡張機能から送信しない。
